# vLLM dual-bank CUDA-fence E2E

This experiment runs the real Qwen3-30B-A3B-FP8 vLLM path with the registered
L0-L3 slot plans. It compares the existing host-synchronized path (`FENCE=0`)
with the main-CUDA-stream compute/completion fence path (`FENCE=1`). Both arms
use two physical 576 MiB banks only to make bank reuse safe; weight copy is not
prefetched over model computation.

The runner deliberately does not load, unload, or reconfigure `nvidia_uvm`.
Each invocation checks that the loaded custom module and all relevant sysfs
parameters already match the requested case. This makes a wrong fence arm fail
before model loading instead of silently falling back to another ioctl.

## Static validation

Build the tiny raw-UVA CUDA fence launcher once:

```bash
make -C ../../workloads/vllm/vllm/uvm_test \
  libuvm_slot_cuda_fence_kernels.so
```

This does not initialize CUDA or run a model:

```bash
./run_case.sh static-preflight
```

It checks shell/Python syntax, the vLLM fence/dual-bank hooks, kernel recipe
telemetry source, and four CPU-only verifier tests.

## Runtime contract

The loaded module must have:

```text
uvm_moe_slot_pte_remap_enable=1
uvm_moe_slot_plan_overlap_copy_prepare=$OVERLAP_COPY_PREPARE  # default 1
uvm_moe_slot_plan_register_pte_prewarm=1
uvm_moe_slot_plan_cache_copy_runs=1
uvm_moe_slot_plan_cache_metadata_recipe=$METADATA_RECIPE     # default 1
uvm_moe_slot_plan_dual_bank_event=1
uvm_moe_slot_plan_cuda_fence=$FENCE
uvm_moe_slot_pool_vidmem_budget_bytes>=1207959552
```

The selected GPU must be at exactly 0 MiB with no compute process before the
case. The runner also waits for that exact state after explicit vLLM shutdown.

Run the two fence cases separately after externally loading/configuring the
matching module:

```bash
ALLOW_GPU_RUN=1 METADATA_RECIPE=1 \
  ./run_case.sh run fence_off 0

# Externally switch or reload the module with
# uvm_moe_slot_plan_cuda_fence=1, then:
ALLOW_GPU_RUN=1 METADATA_RECIPE=1 \
  ./run_case.sh run fence_on 1
```

To isolate the registered metadata-recipe effect, keep the fence choice fixed
and run once with `METADATA_RECIPE=0` and once with `METADATA_RECIPE=1`, again
matching the loaded sysfs value.

Every case uses:

- one vLLM `LLM` instance and exactly three sequential `generate()` calls;
- the deterministic exact L0-L3 plan generated by
  `experiments/vllm_slot_vs_pinned_copy/prepare_inputs.py`;
- `VLLM_UVM_SLOT_DIRECT_CACHE_BYTES=1207959552`;
- `VLLM_UVM_SLOT_DIRECT_MAX_SLOTS=2304`;
- registered plan, fixed-bank reuse, shared push, sliced 64K PTE, dual-bank
event, and eager execution;
- a main-stream signal kernel and completion-wait kernel over the session's
  UVM semaphore-pool VA (no `cuMemHostRegister` dependency);
- disabled weight prefetch and all unrelated dynamic/offload policies.

## Artifacts

The default output is `artifacts/<UTC>_<label>_fenceN_recipeN/`. It contains:

- `result.json` and `slot_trace.jsonl`;
- `latency_stats.before.txt` and `latency_stats.after.txt`;
- `gpu.before.csv` and `gpu.after.csv`;
- `command.txt`, `environment.txt`, `run_config.json`, and module snapshots;
- the generated exact plan and input hashes;
- `verification.json`, containing request latency, registered-plan ioctl
  median, fence acceptance/signal counts, and recipe-cache counter deltas.

The verifier requires successful L0-L3 cycles, dual-bank registration, a
successful session release, copy-run-cache hits, recipe hits when enabled, and
compute/completion fence evidence on every restore when `FENCE=1`.
